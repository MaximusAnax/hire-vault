Decisions Locked In

Captured from the alignment round at the top of the plan so future agents can read context here without re-loading the plan file.

  • Headline replacement. Drop the single Headline UI; replace with Target Roles (chip array) + optional Personal Pitch (one-line free text). Keep the headline column in the DB for backward compatibility but stop surfacing it. Both new fields feed downstream tailoring / interview prompts.
  • Bullet auto-format. Import-time only (resume parse + LinkedIn import). Manual createExperience / updateExperience entries are trusted as written — no per-save AI spend.
  • Summary strategy. Hybrid: per-entity 1–2 sentence snippet cache + one cheap stitch call to assemble 3–5 sentences. Manual "Regenerate Summary" button + a "Profile changed since last assembly" pill. Auto-regenerate the assembled summary only when an entity is added or removed (not on minor field edits).
  • Question bank gating. Per-role, persistent, gated. Generate questions becomes Generate more after the first batch and stays locked until every question in the current bank has practice_rating != null OR practiced = true. The existing bank is passed to the prompt to fill JD gaps without duplicating.
  • Default behaviors applied. Smart-capture accepts URL or pasted JD; best-effort fetch + JD-paste fallback; multi-location free-text chips; 5-star priority UI; gpt-4o-mini for snippet + assemble calls; any self-rating counts as "practiced".
Executive Summary

Iteration 1 polishes the four user-facing surfaces that shipped in phases 1–8 and installs a cost-aware hybrid AI summary engine. Profile editing is now consistent across every section (Experience, Education, Projects, Skills, Courses), the Applications / Jobs page accepts a paste-URL-or-JD with a preview-and-edit card, Resumes always renders the Jobs panel even when the user has zero saved resumes, and Interview Prep gates "Generate more" until the role's bank is fully rated. Phase E added Vitest coverage for the new modules and produced this report.

Architecture WHY

Two new design decisions drove most of the change: the hybrid summary engine and the smart-capture preview flow. Both prioritize spend discipline while still keeping the user in control of the output.

SurfaceChoiceWhy
Profile summary Per-entity snippet cache + single stitch call Field-level edits no longer trigger a full-profile rewrite. Only entity add/remove auto-assembles; everything else is manual. Hash-keyed cache avoids regenerating snippets when the cosmetic content is unchanged (see entityHash).
Headline → Target Roles + Pitch Chip array + one-line pitch A free-text headline gave the model nothing to anchor on. Target roles drive resume tailoring, mock interview tone, and the question generator. Keeping the legacy headline column means imports from old data still work.
Applications add flow Smart capture (URL or JD) + preview card The old 7-field form was hostile to people pasting a single URL. Smart capture detects URLs, runs best-effort scraping (Greenhouse / Lever / Ashby / Workday) with a manual-paste fallback, then shows the AI-parsed fields for review before insert.
Multi-location locations text[] with legacy location mirror Roles often have several locations ("NYC, SF, Remote"). The array column accepts chips; we still write the first chip into the legacy location column so existing queries / displays keep working.
Priority 5-star UI on top of int column Schema unchanged. Better affordance than a number input; star count of 5 is universally read as "highest".
Resumes empty-state Render Jobs panel + tailored CTA Old code early-returned, stranding new users with nothing to click. The two-column shell now renders unconditionally; the empty case becomes a teaching moment, not a dead end.
Interview generation gate Locked until all rated; existing questions in prompt Prevents AI spend on near-duplicate questions and encourages the user to actually practice before requesting more. The dedupe block is buildExistingQuestionsBlock, unit-tested.

1. Hybrid summary engine — packages/ai-core/src/summary.ts

entityHash is the cache key. Normalization collapses whitespace, lowercases strings, sorts object keys, and equates null/undefined so cosmetic edits never bust the cache.

```52:78:packages/ai-core/src/summary.ts function normalizeValue(value: unknown): unknown { if (value == null) return null; if (typeof value === "string") return value.trim().toLowerCase().replace(/\s+/g, " "); if (Array.isArray(value)) return value.map(normalizeValue); if (typeof value === "object") { const out: Record = {}; for (const key of Object.keys(value as Record).sort()) { out[key] = normalizeValue((value as Record)[key]); } return out; } return value; } export function entityHash(entity: SnippetEntity): string { const payload = JSON.stringify({ type: entity.type, fields: normalizeValue(entity.fields), }); return createHash("sha256").update(payload).digest("hex"); } ```

assembleSummary degrades gracefully: without an API key it concatenates snippets and clamps to five sentences so the UI still shows something useful.

```143:217:packages/ai-core/src/summary.ts export async function assembleSummary( snippets: CachedSnippet[], profile: SummaryProfileContext ): Promise<{ summary: string; model: string; degraded?: boolean; error?: string; }> { const cleanedSnippets = snippets.map((s) => s.snippet.trim()).filter(Boolean); if (cleanedSnippets.length === 0) { return { summary: "", model: ASSEMBLE_MODEL, degraded: true }; } const client = getClient(); if (!client) { const fallback = cleanedSnippets.slice(0, 5).join(" "); return { summary: clampSentences(fallback, 5), model: ASSEMBLE_MODEL, degraded: true }; } // …call gpt-4o-mini, then clampSentences to 5… } ```

Known weaknesses (aggregated)

  • Per-domain scraper selectors (Greenhouse, Lever, Ashby, Workday) will rot when boards redesign. The fallback hint nudges users to paste the JD, but there is no monitoring on selector hit-rate.
  • No live integration tests against OpenAI / Anthropic — both AI engines exercise only the degraded path under unit test. A separate sandbox script would be needed to verify prompt quality.
  • Tooltip on "Generate more" is currently a plain title attribute (native browser tooltip). A real @radix-ui/react-tooltip primitive exists in dependencies but is not yet wired here.
  • Applications card lets you edit status / notes but not the underlying job title or company; that flow still requires the manual tab.
  • assembleProfileSummary is invoked synchronously inside create* server actions, which adds latency on add/remove. Acceptable for now (single cheap call), but should move to a debounced background path if user volume grows.
  • The hybrid summary engine assumes profile_summary_snippets rows have entity_ids that match the live row. There's no FK, so an out-of-band delete of an entity will leak a snippet row until the next manual delete.
  • Migration 20260524000100 / ...000200 must be applied manually in Supabase before the new code paths are exercised in production.

Alternatives rejected

  • Render-prop on SectionList instead of split row components — rejected for being type-unsafe across heterogeneous entity shapes.
  • Single full-profile assemble call on every edit — rejected; multiplies cost by N edits per user. Hybrid cache wins.
  • Headless browser for job scraping — rejected; pulls in Puppeteer/Chromium just to bypass bot walls already covered by manual paste.
  • Auto-regenerate the assembled summary on every snippet write — rejected; we still bill for the stitch call. Manual button + stale pill puts the user in control.
  • Auto-rate when "Generate more" is clicked — rejected; makes the gating meaningless. User must self-rate.

"Break this" challenges

  1. Add an experience, then save the exact same row again unchanged → confirm zero new OpenAI calls (regenerateSnippet short-circuits on hash match).
  2. Delete an entity from outside the app (direct SQL) → confirm the cache row remains until assembleProfileSummary is re-run; it should still produce a sensible narrative.
  3. Paste a Greenhouse URL, then immediately paste the rendered JD text → both should produce a similar preview card.
  4. Paste a LinkedIn URL → confirm the blocked banner names LinkedIn and prompts to paste.
  5. Rate 9 of 10 questions, click "Generate more" → button must stay disabled with the tooltip text. Rate the last one → unlocks.
  6. Delete every question in a role's bank → "Generate questions" label returns; existing-questions block is empty.

  1. Run pnpm quality:check. Must pass typecheck, lint, all 23 Vitest tests, and the full build.

Mistake Postmortems

2026-05-24 — Resumes workspace hid Jobs panel on empty resumes

Symptom
New users landing on /resumes with zero tailored resumes saw a single CTA card and no way to discover that they had to start from a Job on the Jobs panel. The Jobs panel itself was never rendered.
Root cause
ResumeWorkspace early-returned at lines ~78–86 in the original implementation when resumes.length === 0. The early return bypassed the two-column layout that owned the Jobs panel.
Fix
Removed the early return. Jobs panel and Versions list are now part of the unconditional shell; the right column shows a teaching CTA when no resume is selected (see components/resumes/resume-workspace.tsx lines 81–158).
Should have caught
A "zero resumes, ≥ 1 job" smoke test, or a manual onboarding walkthrough as a checklist item before shipping Phase 5.
Prevention added
Phase E added scrape.ts fixture tests + interview bank unit test; mistake tracker now flags "empty-state regressions" as a recurring pattern with a rule that every list component needs a Vitest / Storybook case for data = [].

2026-05-24 — Interview bank rendered every job's questions for the selected role

Symptom
When selecting Role A in InterviewPrep, the question bank section listed questions belonging to Role B as well. Practice ratings were correctly per-question, but the bank read like a global pile.
Root cause
The original component iterated questions directly (the union of every user's questions across jobs). There was no filter((q) => q.job_id === jobId) step, and the bank section rendered even when no role was selected.
Fix
Derived jobQuestions at the top of the component and consumed it everywhere downstream (bank list, gating, current flash question). Hid the entire bank Card when jobId is empty. See components/interviews/interview-prep.tsx lines 50–67 and 218–263.
Should have caught
A unit / integration test that seeds two jobs with one question each and verifies the bank section only renders the active job's question. Cross-job leakage is a classic case the typechecker can't see.
Prevention added
Phase E added scrape.ts fixture tests + interview bank unit test (the new buildExistingQuestionsBlock helper + its Vitest spec catch the second half of this class of bug — that the dedupe prompt embeds only the current role's questions); mistake tracker pattern entry covers the broader "filter the active scope" rule.

Both rows are appended to reports/mistake-tracker.md with severity = functional, "Caught by automated gates: No", and prevention measure "Phase E added scrape.ts fixture tests + interview bank unit test".

Next Steps
  • Snippet engine bulk-debounce: today every create* server action awaits regenerateSnippet + assembleProfileSummary serially. Move the assemble call onto a debounced background job so a profile-import storm doesn't block the user.
  • Scraper fixture coverage: the current Phase E test covers Greenhouse only. Add fixtures for Lever, Ashby, and Workday so a board redesign breaks a test instead of a user.
  • Real Tooltip primitive: replace the native title on "Generate more" with the existing Radix tooltip so the gating reason is visible on touch devices too.
  • Real-edit UI for applications: today the application card edits status + notes but not the job's title / company / locations. Add an inline edit pop-out so users don't have to delete + recreate to fix a typo.
  • Snippet-cache GC: a periodic sweep to remove profile_summary_snippets rows whose entity_id no longer resolves in its source table.
  • Cost telemetry: log {model, prompt_tokens, completion_tokens} on every generateSnippet / assembleSummary / polishBullets call so we can validate the "hybrid is cheaper than full-profile" claim with real data.
  • Drop legacy headline once data has been migrated to target_roles / pitch across all imports.
