Executive Summary

Phase 1 delivers the HireVault foundation: a Turborepo monorepo with a Next.js 15 web app, shared types, Supabase schema with RLS, Linear-inspired dark UI (sidebar + Cmd+K), Google OAuth auth, and full profile CRUD for five sections.

  • Scaffold: pnpm workspaces, turbo.json, pnpm quality:check
  • Database: Full ER schema migration + RLS + auto-profile trigger on signup
  • UI: shadcn/ui, dashboard shell, command palette
  • Auth: @supabase/ssr cookies, middleware, OAuth callback
  • Profile: Server Actions for create/delete + forms per section

Risk Assessment
  • Supabase not linked: OAuth and CRUD fail until .env.local is set and migration applied.
  • handle_new_user trigger: Existing users before migration need manual profile insert.
  • No edit-in-place: Profile sections support add/delete only; inline edit is Phase 2.
  • Extension paths: manifest references built JS paths; build pipeline is Phase 4.

Known weaknesses

  • No automated RLS policy tests yet.
  • Database types are hand-written, not generated from Supabase CLI.
  • User menu does not load Google avatar from session metadata.

Break this

  • Visit /profile without running migration — expect empty/error states.
  • Sign in as two users; confirm user A cannot read user B's experiences via API.
  • Submit experience form with empty company — should fail validation at DB.

Verification playbook

2 min: pnpm install && pnpm quality:check

10 min: Apply migration, set env, pnpm dev, Google login, add one experience, refresh page.

Deep dive: Read middleware.ts, migration RLS policies, user_owns_profile() function.

Questions to ask

  • What happens if Google OAuth redirect URL is wrong?
  • Where is the test proving RLS blocks cross-user reads?
  • Why Server Actions vs API routes for profile mutations?
Learning

Why @supabase/ssr: Refreshes JWT in middleware and stores session in cookies — Server Components can call getUser() without client hydration.

Why RLS: Even if the anon key leaks, Postgres policies restrict rows to auth.uid().

Dig deeper: Supabase Next.js Auth, shadcn/ui
